# EPD Studio

面向 NRF_EPD 墨水屏的本地创作与蓝牙控制台。使用 React、TypeScript、Vite 和 shadcn/ui，在浏览器中完成画面编辑、像素处理、作品管理和设备发送，无需后端服务。

## 功能

- **创作工作台**：文字、图片、矩形、线条、二维码及图层管理；支持撤销重做、旋转、翻转、尺寸适配和多图层操作。
- **图片直传**：导入或粘贴图片，调整裁剪与适配方式，预览处理结果后发送到设备。
- **本地模板**：通过模板字段生成画面，包含作业等内容模板；设备内置日历与时钟单独由固件绘制。
- **像素处理**：支持黑白、黑白红、黑白红黄调色板；集成 EPD Optimize 和 OpenDisplay 两种处理引擎，可调整抖动、亮度、对比度等参数。
- **作品管理**：显式保存作品，导入导出作品 JSON、完整工作区 JSON 备份及最终 PNG 图片。
- **设备中心**：连接、断开、查看固件与配置、设备别名、校时、日历与时钟模式、驱动和引脚配置、清屏与休眠。
- **发送记录**：保存发送结果与错误信息；支持取消、传输进度、协议诊断日志，以及最近已授权设备的启动重连。

## 运行要求

- **Node.js**：当前锁定的 Vite 要求 `^20.19.0 || >=22.12.0`，可使用 Node.js 22.12+ 或 24，并配套使用 npm。
- **浏览器**：蓝牙操作需要支持 Web Bluetooth 的电脑端 Chrome 或 Edge，以及可用的系统蓝牙适配器和权限。具体可用性取决于浏览器与操作系统提供的能力。
- **访问环境**：蓝牙连接需要安全上下文；本地使用 `http://127.0.0.1` 或 `http://localhost`，远程部署使用 HTTPS。普通局域网 HTTP 地址不满足该要求。
- **设备**：需要实现本项目 EPD 蓝牙协议的固件。型号列表是软件内置配置，不代表已经逐一完成实机兼容测试。

不连接设备时仍可使用本地创作、像素处理与文件导出功能。

## 快速开始

克隆仓库后，在项目根目录执行：

```powershell
git clone https://github.com/meesii/epd-studio.git
cd epd-studio
npm ci
npm run dev
```

打开 [http://127.0.0.1:5178/](http://127.0.0.1:5178/)。开发服务仅绑定本机地址，端口 `5178` 被占用时会直接报错。

### 构建与预览

```powershell
npm run build
npm run preview
```

`build` 先执行函数命名检查和 TypeScript 类型检查，再生成 `dist/` 静态文件。预览服务默认使用 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)，端口占用时会尝试其他端口，以终端显示的地址为准。

部署时发布 `dist/` 并使用 HTTPS。如果托管在仓库子路径下，需要按实际路径配置 [vite.config.ts](vite.config.ts) 的 `base` 后重新构建。项目当前未配置自动部署流程。

## 使用流程

1. 打开“创作工作台”新建作品、选择“本地模板”，或在“图片直传”导入图片。
2. 设置实际屏幕尺寸和调色板，编辑图层并预览最终像素；需要保留编辑结果时点击“保存作品”。
3. 在“设备中心”连接设备。默认只显示名称以 `NRF_EPD` 开头的设备，可关闭名称过滤；连接前先唤醒设备，并断开手机等其他客户端的连接。
4. 核对识别到的型号与配置。配置未成功识别时，需要手动选择实际型号；修改驱动和引脚前应确认与硬件一致。
5. 发送画面并查看结果，等待实体屏幕刷新。发送完成后仍需目视确认显示效果。

首次蓝牙授权需要用户点击并在浏览器选择器中选择设备。启动自动重连只尝试最近成功连接且仍已授权的设备，依赖浏览器的 `getDevices` 能力；不会绕过首次授权。

## 保存与数据

作品和图片在本地浏览器中处理。已保存工作区使用 IndexedDB；蓝牙重连偏好与最近设备标识保存在 localStorage，没有服务端同步。

- 新建、模板、复制、导入及后续编辑首先修改内存草稿，点击“保存作品”或按 `Ctrl+S` / `Cmd+S` 后才加入或更新“我的作品”。关闭或刷新页面不会自动保存草稿。
- 切换创作草稿时，可选择保存、放弃或取消。发送记录独立保存，发送草稿不会自动将其加入作品库。
- 完整工作区备份包含已保存作品、发送记录和设备别名，不包含未保存草稿；草稿可单独导出为作品 JSON。
- 恢复工作区备份会替换已保存工作区；删除作品、恢复备份前可先导出当前数据。
- 浏览器数据按站点来源隔离。更换协议、域名或端口会进入不同的本地存储空间；清除站点数据会删除对应来源的作品，请定期导出备份。
- 导入和导出的 JSON 文件上限为 10 MB；当前校验允许最多 100 个已保存作品、每个作品 200 个图层和 1000 条发送记录，作品尺寸每边为 1–2000 像素。

## 屏幕与协议范围

[型号配置](src/lib/ble/models.ts) 包含 4.2 英寸与 7.5 英寸屏幕，覆盖 `400×300`、`640×384`、`800×480` 和 `880×528` 分辨率，以及 UC8176、SSD1619、JD79668、UC8179、UC8159、SSD1677 驱动组合。具体调色板以型号配置为准。

支持校验协议的固件使用逐块 CRC / ACK 和会话状态检查；旧版或版本未知的固件使用带响应的兼容传输。断连或失败后需要重新发送整幅画面。取消发送无法撤回已经发出的刷新命令。

当前协议没有物理刷新完成回执：成功结果表示画面数据已发送并提交刷新请求，界面中的刷新等待时间仅为估算。内置日历与时钟的版式由固件决定；自动化任务与 OTA 升级向导尚未实现。

```text

│  │  ├─ studio/         # 场景模型、模板、渲染与像素处理
│  │  └─ storage.ts      # 工作区校验与本地持久化

├─ package-lock.json     # npm 依赖锁定文件
└─ vite.config.ts        # 构建配置与开发端口
```

## 开发约定

- 项目自有普通函数、方法及函数型回调使用 `snake_case`，例如 `save_workspace`、`read_image`；命名应简短且具有明确含义。
- React 组件及类型使用 `PascalCase`；自定义 Hook 使用 `use_` 前缀，例如 `use_workspace`、`use_device`，第三方 React Hook 保持原名。未来接入 React Hooks lint 或编译器时，须确认其支持该命名方式。
- React、浏览器、第三方库要求的 API、回调属性和适配接口保留原名，例如 `useEffect`、`requestDevice`、`getImageData` 和 `onClick`。
- 文件名使用 `kebab-case`，缩进跟随项目。关键函数补齐多行 JSDoc，并说明参数与返回值。
- `npm run check:names` 单独检查自有函数、方法、函数型变量与回调命名；提交前执行 `npm run build`，会同时执行命名检查、类型检查及生产构建。涉及蓝牙协议、屏幕配置或像素输出的修改，还需用对应设备和画面核验。目前未配置独立的功能测试命令。
